# PowerShell marketplace boundary

The adapter may route to a named local PowerShell skill such as filesystem
list/read/update, invoke, checks, or a domain validator. The catalog returns
the script path and declared grant; the orchestrator supplies device and scope.

Default mode is dry-run. A real process needs an exact script or executable,
validated arguments, a working-directory boundary, a finite timeout, and capped
output. A non-zero result becomes evidence for CHECK or a LOOP seed; it does not
become a maker-authored verdict.

No adapter entry grants credentials, arbitrary commands, or system-root access.
GitHub operations require a separate repository skill and authorization cycle.
