# Product repository contract

The product repository is a reusable operating surface, not an unrestricted
agent. It contains a manifest, agent identities, a revocable autonomy grant,
generic trail protocol, validators, tests, and progressive activation notes.

The normal route is:

`skill.create.request -> orchestrate -> plan -> make -> check -> reflect`

Routine local operations may continue when the active grant names the
repository, paths, tools, data class, deadline, and finite limits. The
orchestrator owns continuation. A maker creates artifacts; a separate checker
issues the verdict; the reflector records one unexecuted next seed.

Provider adapters such as Codex, Claude, Ollama, MAF, MCP, Desktop Commander,
Harness, or CodeAct are capability surfaces. They inherit the product grant
and do not widen it. A connection is not authority.

External writes, credentials, deletion, package installation, releases,
publishing, and GitHub pushes require a new explicit policy decision and a
fresh checker cycle.
